Recommended operating model

  • GitHub repo: active SIP Suite landing pages, reusable components, builder tools, shared styles/scripts, and this inventory page.
  • Cloud asset vault: PDFs, PowerPoint, Word files, screenshots, MHTML captures, and non-code support material.
  • Archive: old numbered HTML iterations that are useful for forensic reference but not part of the live working spine.
  • Library in your folders: move reusable section patterns and utilities into library/ so they can be pulled from any machine.
Rule of thumb: if you actively build from it, commit it. If you mainly reference it, store it in the asset vault. If it is old but still useful, archive it outside the active source path.

Workflow rules

  • Use branches for meaningful design or content changes rather than creating another standalone file version.
  • Keep only one primary active landing page in src/landing-pages/.
  • Move duplicate numbered iterations into archive/ once their useful sections are harvested.
  • Store PDF, PPTX, DOCX, and MHTML files in a shared cloud folder such as SIP Campaign Assets/.
  • Name files by function, not panic: avoid chains like final-new-updated-v2.
