Git + VS Code: the “no-zip, two-computer” workflow

Built for: switching between a Mac and a work computer, minimal Git experience, and a strong need for clean organization + version control.

Repo: https://github.com/alyssavwheaton-lab/sip-files
Target branch: main
Date: March 17, 2026
Your default rule

Clone once on each computer. After that: pull to get updates and push to send updates. No ZIP downloads.

Golden path:
Edit in VS Code → Commit → Push → Switch computers → Pull → Continue.
Step 1 — Do this on BOTH computers (one-time)

You’ll do a one-time “clone” on your Mac and your work computer. After that, you never download ZIPs.

1A) Install the basics (Mac) 
Open Terminal and run:
xcode-select --install
This installs Apple’s command-line tools, including Git.
1B) Install Git (Windows work computer)

If your work computer is Windows, use “Git for Windows.” If IT blocks installs, ask for Git + VS Code approvals.

Confirm Git is installed:
git --version
1C) Clone the repo and check out your branch

Run these commands in Terminal (Mac) or PowerShell (Windows). Choose a folder you’ll remember (e.g., Documents).

cd ~/Documents
git clone "https://github.com/alyssavwheaton-lab/sip-files.git"
cd sip-files
git fetch origin
git checkout "main"
1D) Open the project in VS Code

Two easy ways:

  • From Terminal: run code . inside the repo folder
  • From VS Code: File → Open Folder → select the sip-files folder
From inside the repo folder:
code .

Version control (simple rules that work)

You don’t need a complex branching strategy. Use a predictable pattern that you can repeat.

WhenWhat you doWhy
Small edits (copy, spacing, small component tweaks)Work directly on mainFast, fewer moving parts.
Big changes (new layout, new module, refactors)Create a new branchSafety: you can abandon/compare easily.
Milestones you may need to revert toCreate a Git tag“Save point” that won’t move.
Create a new branch (for bigger work) 
cd ~/Documents/"SIP Files — ARCHIVED 2026-03-10"/GitFiles/sip-files
git checkout "main"
git pull
git checkout -b "claude/build-8-hero-refresh"
git push -u origin "claude/build-8-hero-refresh"
Make a “save point” tag (optional, but useful) 
git tag -a "build-7-approved" -m "Approved build 7 checkpoint"
git push origin "build-7-approved"
Conflict avoidance:
Do not edit the same file on both computers without pushing/pulling in between. Always push from the first machine before editing on the second.
Folder structure to prevent chaos

Only dist/sfmc/ is considered “deployable.” Everything else is work-in-progress or build output.

Troubleshooting (the common issues)
“I changed something on my Mac, but I don’t see it on my work computer.”
  1. On the Mac: Commit + Push
  2. On the work computer: Pull
Mac:
git add -A
git commit -m "Describe the change"
git push

Work computer:
git checkout "main"
git pull
“Git says I have changes but I didn’t mean to change anything.”

Often caused by formatting, line endings, or build output. Inspect first, then decide.

git status
git diff
“I’m afraid to break things. Can I undo?”

Yes. Two safe options:

  • Discard local edits (not committed): git restore .
  • Undo a committed change: use “Revert” in GitHub UI or run git revert <commit>
# Discard uncommitted edits:
git restore .

# See recent commits:
git log --oneline --max-count=10
“VS Code can’t find the project / I keep opening random files.”

Always open the folder, not a file. Use: File → Open Folder → sip-files.

“Authentication / permissions issues when pushing.”

Most common fixes:

  • Sign into GitHub in VS Code (Accounts icon) and retry push.
  • Use a Personal Access Token (PAT) if your org blocks credential helpers.
  • If your work machine has strict IT controls, GitHub Desktop sometimes passes approval faster than CLI.
